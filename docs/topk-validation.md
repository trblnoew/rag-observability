# Top-K 오프라인 비교 실습

## 무엇을 확인하나요?

Threshold는 점수 합격선, Top-K는 최대 반환 Chunk 개수입니다. 이번에는 합격선을 **0.3**으로 고정하고 **K=1/2/3/5**만 바꿉니다. 기존 새 질문 18개의 검색 결과를 재사용합니다. 질문·정답·원본 보고서는 수정하지 않습니다.

1. 기존 로더로 COMPLETE·해시·순위·검색 조건을 검사합니다. 잘못된 답안지로 채점하지 않기 위해서입니다.
2. 점수가 0.3 이상인 결과 중 앞의 K개를 선택합니다. 같은 문서의 여러 Chunk도 그대로 셉니다.
3. 정답 문서의 첫 등장 순위로 Hit와 RR을 계산합니다. 답 없는 질문은 Hit/RR 분모에서 제외합니다.
4. 네 조건의 보고서를 새 폴더에 저장합니다. 원본을 보존하므로 언제든 같은 실험을 반복할 수 있습니다.

## 실행

프로젝트 루트 PowerShell에서 실행합니다. Java 21과 Maven이 필요하며, 의존성 다운로드 외에는 네트워크 작업이 없습니다. Spring·Docker·DB·API Key는 필요 없고 `.env`도 읽지 않습니다.

```powershell
.\scripts\compare-topk.ps1 -BaselineDir "evaluation/results/2026-09-05T11-49-05.080986300Z-37efaa7c-f685-45ec-8dd4-ee87aac55c07"
```

API 호출은 **0회**입니다. `Top-K comparison COMPLETE` 뒤에 출력된 경로의 `summary.md`를 엽니다. 입력 오류는 비정상 종료하며 성공 보고서를 남기지 않습니다. 입력 경로는 필수이고 최신 폴더를 자동 선택하지 않습니다. 기존 15개 baseline도 지원하지만 새 데이터셋과 합산하지 않습니다.

## 결과 읽기

- `comparison.csv`: K별 전체·유형별 지표와 분모, 데이터 4행.
- `query-comparison.csv`: 질문·정답·판단 근거와 각 K의 채점, 새 질문 기준 데이터 72행.
- `summary.md`: 비교표, K=5 대비 놓친 정답, K 증가로 새로 찾은 질문, 원본 해시와 Git·모델·조건 기록.

Hit@K는 정답 문서를 찾은 비율, MRR@K는 첫 정답의 역순위 평균입니다. 평균 Chunk 수는 반환 자료량이고 평균 고유 문서 수는 반환 문서 종류 수입니다. 고유 문서 수를 계산해도 채점 순위에서 문서 중복을 제거하지는 않습니다.

이번 실제 결과에서는 K=1의 Hit 10/12, MRR 0.8333, K=2/3/5의 Hit 12/12, MRR 0.9167이 예상됩니다. 결과에 맞추려고 질문이나 정답을 바꾸지 않습니다.

## 해석상 한계

- threshold가 같고 K가 1 이상이면 결과 존재 여부는 같습니다. 따라서 빈 결과율·부정 질문 반환율은 K를 바꿔도 일정합니다.
- K=2와 K=5의 문서 검색 성공률이 같아도 답변에 필요한 Chunk가 모두 포함됐다는 뜻은 아닙니다. RAG 답변 품질은 별도 평가 대상입니다.
- Chunk 전문이 없어 token 수·LLM 비용 절감량을 계산하지 않습니다. 지연시간도 새로 측정하거나 기존 latency를 재사용하지 않습니다.
- 저장된 순위는 최대 5위입니다. K>5는 이번 도구에서 지원하지 않습니다.
- 기존 600-token 생성 조건은 운영자 전제입니다. DB를 변경하거나 재분할하지 않습니다.
- RAG 기본 threshold **0.5**, Top-K **5**는 유지합니다. 실험 결과가 운영 설정을 자동 변경하지 않습니다.
